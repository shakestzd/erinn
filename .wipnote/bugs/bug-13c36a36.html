Windows build is broken, while windows-tagged files imply support

Todo Medium Priority

Part Of:

  • trk-2c55adea

Description

Cross-compiling for Windows fails: a session-family helper calls the Unix flock syscall directly with no build tags, so the constant and function are undefined on that platform. The break predates tonight's work and sits outside the file-lock package. This matters mainly because the codebase carries windows-tagged files in two lock packages, which implies the platform is supported, while the module does not compile there at all — so the previously filed cross-process lock gap on Windows is moot until this is resolved. Two honest resolutions and the choice should be deliberate: either Windows is a supported target, in which case fix the build and add a cross-compile check to the gate so it cannot regress unnoticed, or it is not, in which case drop the windows-tagged files rather than shipping code that implies a platform nobody tests. Leaving it as-is is the one option that misleads.
