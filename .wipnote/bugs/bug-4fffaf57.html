wipnote does not install its derived/runtime .gitignore policy into adopter projects — session/telemetry/lock/pid artifacts show as untracked

Description

The wipnote dev repo's root .gitignore hand-maintains a 'wipnote policy' block ignoring derived/runtime artifacts (.wipnote/sessions/, events/, logs/, *.db*, **/*.lock, .active-session, .launch-mode, .otlp-port, etc.). Adopter projects never receive this policy — the only gitignore writer is excludeWipnoteFromWorktree (worktree-scoped). So in a user project, all of wipnote's runtime/telemetry files (sessions/*.html, events.ndjson, *.lock, .collector-pid, .index-offset, .active-session, .otel-notice-shown, session-families.json, migrations/*.done, etc.) show as untracked: pollutes git status, risks accidental commit, and floods the yolo worktree-carryover 'Untracked files not carried' output (~100 lines of wipnote internals). Fix: (1) idempotently install a self-contained .wipnote/.gitignore policy (patterns relative to .wipnote/) at project bootstrap / session-start for ALL harnesses, ignoring derived/runtime/telemetry while keeping canonical work-item HTML + config tracked; (2) top up patterns missing from the current dev policy (.otel-notice-shown, session-families.json, migrations/*.done, pid/offset markers); (3) defensive: exclude .wipnote/ from the carryover untracked report in internal/worktree/carryover.go. Rationale for ignoring sessions: per-user/per-machine observability, unbounded churn, sensitive prompt/cost content, fully derived — the portable causal backbone is committed work-items + git commits, not local session traces.
