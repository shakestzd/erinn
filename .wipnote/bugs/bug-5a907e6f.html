So these edges are not born in SQLite with no backing; they are derived from canonical artifacts that happen not to be work-item HTML. Writing them INTO work-item HTML would be wrong — it would create a third copy of facts the YAML and ledger already own, exactly the duplication this session spent the night removing. What remains real from the original filing: any reader built over work-item HTML alone sees none of these edges, so tests over that surface can pass vacuously — the bottleneck-filter trap stands. The remaining work is therefore observational, not structural: extend the edge census test to compare canonical declarations plus documented derivations against the index, so the derivation contract is enforced rather than assumed.
