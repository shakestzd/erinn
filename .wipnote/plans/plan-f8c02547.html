DesignPending

Problem

Plan documents are not read. Measured over 45 plans and 282 slices: what, done_when, why and tests are 74.8% of all words; median plan is 9.3 minutes of reading and the worst is 27. Words per slice rose 77% while slices per plan fell 22% — plans are not getting structurally complex, individual slices are getting verbose, because critique appends instead of revising. The "visual" block catalog does not draw. 22 block instances are authored across the corpus (12 file-tree, 4 diagram, 4 data-model, 1 wireframe, 1 tabs, 0 api-endpoint); they render as 34 instances because blocks are emitted by both blocks_zone and visual_overview_zone. Zero of either figure contain an svg or canvas element, by explicit design — plan/blocks/diagram.go states it is "deliberately Mermaid-free and uses pure HTML/CSS (no client-side layout engine, no SVG text-measurement)". file-tree has no indentation logic at all, so 3 files and 30 files render identically flat; diagram joins bordered divs with a Unicode arrow glyph rather than a drawn edge. The one component with real rendering machinery — the dependency graph — emits an EMPTY svg and is built client-side by d3 plus dagre-d3 from a display:none data island, so it is invisible in archived, offline and no-JS views. Block adoption is NOT the problem: blocks-first shipped 2026-06-21 and 43 of 45 plans predate it; the single organic post-launch plan reached 8 of 8 block coverage unenforced. The feature works as designed. The design produces text.

Goals

  1. Give the block catalog a real drawing primitive: static inline SVG generated in Go at render time.
  2. Make the dependency graph exist in the committed artifact, readable with no JavaScript.
  3. Stop per-slice prose inflation at its source: critique revises in place, and `what` is capped.
  4. Close the default-tier block gap without breaking in-flight drafts or the 42 legacy plans.
  5. Remove catalog dead weight: api-endpoint has never been used in 282 slices.

Constraints

  • No cgo, no external binary, no network fetch at render time. A pure-Go embedded dependency is acceptable where it removes custom-algorithm risk.
  • Rendered output must be self-contained: no external font, script, stylesheet or runtime fetch.
  • Legacy plans re-render lazily on next mutation. The d3/dagre-d3 vendor assets stay on disk until the last legacy plan is migrated.
  • `wipnote plan validate` must accept BOTH the legacy d3 format and the new inline-SVG format for the whole migration window.
  • Must not break plan review: the feedback DOM contract (data-section, data-block-anchor, anchor scheme) is load-bearing.
  • Plan HTML is the retrieval corpus for `wipnote relevant` (rg --type html) and `wipnote find plans`. Emitted labels must stay greppable as contiguous text.
