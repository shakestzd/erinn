Re-review job 482 (F, 2 Med, plateaued). (1) core/daemon/socket.go async dedup: an in-flight duplicate (2nd client, same op_id, while 1st pending) gets AckDuplicate and skips fallback; if 1st apply fails the duplicate is lost. Fix: track pending vs applied op_ids separately; do NOT return durable AckDuplicate for a still-pending op (re-enqueue it / treat as non-durable so caller falls back); only confirmed-applied ops dedup durably. (2) core/db/open_modes.go OpenWithBusyTimeout wraps runMigrations in RetryOnBusy(DefaultBusyBackoff ~2.6s), so a bounded hook open (OpenHookDBWithBusyTimeout) on a stale/unmigrated DB under a held lock exceeds <1s. Fix: skip migration when DB schema already current (cheap read check), and for the bounded open keep migration within the bounded timeout (no separate 2.6s retry). LAST capped fix pass per user.
