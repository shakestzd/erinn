Description

The agent id column added to the telemetry signals table tonight does not exist in the live database, confirmed by a direct schema query, while signals continue to be written. A full reindex threw thousands of repeated errors reporting the missing column. The migration itself is correct and sits immediately beside an earlier one for the feature id column that did apply — the difference is only that the earlier one has had a dashboard launch since it landed. The schema function's own comment states that existing databases pick the change up on the next serve invocation, so the migration is gated behind an optional command while the write path depends on the column unconditionally. Anyone who never starts the dashboard never gets the column, and the per-signal agent attribution shipped tonight is silently inert for them while generating error spam. Two things to fix: apply schema migrations wherever the database is opened for writing rather than only on serve, and make the writer's dependency explicit so a missing column fails loudly at startup instead of once per insert. Note this also caps confidence in the reindex, since thousands of swallowed write errors during a rebuild mean the resulting index is incomplete in ways nothing reports.
