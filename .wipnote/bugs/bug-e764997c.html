Description

MEASURED ROOT CAUSE, which is neither of the two originally suspected. A bare immediate transaction with a single insert and commit costs 14.8 microseconds per signal. The full write path including agent and feature resolution costs 865 microseconds — real overhead at 58 times the floor, but nowhere near the 63 milliseconds observed. The gap is a metric retention prune that runs unconditionally once per session on every write call, regardless of whether the signal just written is even a metric. Its cost scales with the session's metric row count and does not fall away once pruned: 82 microseconds at zero rows, 4.3 milliseconds at two thousand, 52.6 at ten thousand, 149 at twenty-five thousand, and 12.9 milliseconds per call in steady state at the five thousand keep limit — because the delete carries an ordered subquery that re-sorts the session's entire metric set on every call whether or not anything changed. One session in the real corpus holds 86761 signal lines of which 7715 are metrics, and since the writer is called once per signal that session alone issues roughly 86000 unconditional prunes at 13 milliseconds each — 18 to 19 minutes from one session's prunes before counting six others. FIX: guard the prune so it runs only when a metric-kind signal was actually written in that batch. Provably equivalent, since skipping a prune when nothing metric-shaped changed cannot alter which rows survive. This supersedes the earlier plan of partitioning by harness and resource attributes and hoisting resolution out of the loop — both remain true observations about the write path but neither is the dominant cost. Acceptance Criteria Full real-corpus reindex time re-measured after the guard. Batch containing no metric signal skips the prune; batch containing one still prunes correctly. Surviving rows identical before and after on the real corpus.
