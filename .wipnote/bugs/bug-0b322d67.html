Description

workItemHasLiveHeartbeat in cmd/wipnote/config.go queries the claims table, which no hydration pass populates and which an audit found may have zero production writers. The guard therefore always returns false, leaving only an mtime TTL, a git-lock check and a clean-tree check between a live agent's worktree and git worktree remove. A live agent idling on a clean tree satisfies all three. Mitigated today only because EmptySpikeWorktreeCleanup defaults to false and no project config enables it. The loop's comment describes it as liveness-aware, which is false and must be corrected regardless of whether the guard is fixed.
