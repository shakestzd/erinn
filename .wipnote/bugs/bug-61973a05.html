Description

The command package test run has twice produced a bare package-level FAIL after roughly 160 to 180 seconds with no named failing test anywhere in the output — no line identifying which test failed, just a stream of subprocess CLI output ending abruptly. That shape indicates a hard crash or a direct process exit rather than an assertion failure. The consequence is worse than one broken test: when the test binary dies partway through, every test scheduled after it never runs, and the output gives no indication of how much was skipped. A suite that aborts silently is indistinguishable from a suite that ran fully and found one problem, which means coverage loss is invisible and any real failure sitting later in the run is masked. Observed independently by two agents on different trees, so it is reproducible rather than incidental. Identify the crashing test — running with the verbose flag, or bisecting by running subsets, should reveal where output stops. Likely candidates are tests that spawn the CLI as a subprocess or any path that reaches a direct process exit in test context. Once identified, the fix must both repair the crash and ensure a future crash is attributable rather than anonymous.
