git_commits primary key collision drops all but the first work item on multi-item commits

Done Medium Priority

Implemented In:

Part Of:

  • trk-08dcbb33

Description

git_commits has primary key (commit_hash, session_id) and the trailer-ingest path writes a constant session_id of trailer-ingest for every row. With INSERT OR IGNORE, a commit whose message references two or more work items only ever keeps the first, silently discarding the rest. Measured across full history: 30 of 2392 strict-pattern-matching commits carry multiple IDs and lose linkage this way. Compounds the -500 cap issue filed alongside this. Fix by making the key admit multiple work items per commit, or by writing one row per referenced item.
