Measured: only about 4200 of 84000 rows in the derived DB mirror canonical HTML (graph_edges 3096, features 912, arch_cards 174). The rest is telemetry (otel_signals 36854, agent_events 7391) and git-derived cache (feature_files 24242, git_commits 10325). wipnote find and relevant already bypass SQLite entirely, reading HTML directly. Investigate whether SQLite can be removed completely: what local-first tools with file corpora actually use (Logseq's in-memory DataScript, Obsidian, TiddlyWiki, Foam), whether append-only JSONL plus compaction covers telemetry, what an in-memory graph costs at 3096 edges over 1026 documents, and what breaks — aggregation, dashboard queries, concurrent hook writes. Note the single-writer daemon exists BECAUSE of SQLite contention, so removing it may simplify more than the DB itself.
