Description

The reinvent-the-wheel rule is well written but purely advisory, and nothing checks it when a new component is designed. Documented consequence in GitHub issue 171: a prior session hand-rolled a roughly 280 line SSE frame parser when a maintained crate implementing the same WHATWG algorithm had 17.5 million downloads, and a later session then defended the hand-rolled code in a written architectural recommendation without searching. The cost was not line count — CRLF framing was the one thing the parser existed to get right, its JavaScript twin split on the wrong terminator so no events ever dispatched, and that masked three separate misdiagnoses. Three enforcement options were proposed. The plan gate is the most promising because the machinery already exists: the v4 validator enforces per-slice research citations, so extend it so a slice creating a new non-trivial module must carry a named adopt-vs-build decision citing either the adopted package or the evaluated and rejected candidates. Second option is a completion check that flags a work item adding a new module above a size threshold with no recorded decision. Third is a dedicated arch card kind so the decision becomes a first-class greppable artifact rather than prose buried in a slice. The third is cheap and complements either gate.
