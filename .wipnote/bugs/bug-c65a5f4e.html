Description

models.Node.Properties is a real map that EditBuilder.SetProperty writes to, and production CLI paths use it — standalone_reason, created_in_session and affected_files are all set during work item creation and plan orphan migration. But nodeTemplateData lists every article attribute by name and never includes Properties, and parseDocument reads a fixed list of data attributes and never repopulates it. Confirmed by grep: zero HTML files under the store contain standalone_reason or created_in_session. The values are written to an in-memory map and discarded at the write boundary. Concrete consequence: isOrphanFeature reads Properties for standalone_reason, so it is dead code after any disk round-trip, and plan migrate-orphans --apply would re-mark the same features on every run because the marker never persists. This is the third instance this session of the same pattern — a field that exists in the model but is never rendered or parsed, after plan edges were never scanned and edge properties were never rendered. Fixing it delivers the generic node-level data attribute mechanism that the telemetry rollup also needs, so the two should share one implementation. Note that a full fix is three edit points, not two: the template for write, the parser for read, and indexWorkitemNode plus the features schema for the SQL surface.
