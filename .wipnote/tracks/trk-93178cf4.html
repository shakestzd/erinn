Description

Systemic issue surfaced 2026-05-29: wipnote implemented many Claude Code hook handlers with one observe-only template (recordSimpleEvent + {continue:true}) regardless of whether the event is observational, additive-controlling, or replacement-on-registration. CRITICAL instance: WorktreeCreate is a replacement hook (registering it replaces CC native git worktree creation per code.claude.com/docs/en/worktrees) but wipnote only observed it, breaking ALL Agent(isolation=worktree). Additive-controlling events (PermissionRequest, PreCompact, SubagentStop, TeammateIdle, PostToolUseFailure) are observe-only = unused capabilities, not breakage. Durable solution: (1) fix WorktreeCreate by removing its registration so CC creates natively; (2) add a hookEventContractSpecs build-time guard (analogous to agentFrontmatterFieldSpecs) classifying each event and asserting registration/handler-shape correctness; (3) optionally adopt the latent controlling capabilities + decode missing CloudEvent input fields.
