feature_files stores both absolute and repo-relative paths for the same file, duplicating rows

Todo Medium Priority

Part Of:

  • trk-08dcbb33

Description

The schema comment states paths are stored repo-relative with absolute paths normalized at write time, but the PostToolUse hook write path does not normalize. The same file therefore appears twice for one work item: once relative (from the commit-derived reindex path) and once absolute (from the hook path). Measured: 286 absolute rows against 23956 relative, with 152 confirmed duplicate pairs where one row is the host-prefixed form of the other. Visible in trace --tests output as two entries for one test file. Consequences: inflated file counts, UNIQUE(feature_id, file_path) failing to dedupe as intended, and host-specific prefixes leaking into an otherwise portable store. Normalize to repo-relative at every write site and migrate existing rows. Note wipnote's own check-host-paths gate blocked the first draft of this description for quoting such a path, which is the gate working correctly.
