The orchestrator directives shipped in the wipnote system prompt instruct agents to batch calls including 'wipnote feature edit' as a bookkeeping command. No edit subcommand exists on feature, bug or spike. Running 'wipnote bug edit <id> --description ...' fails with 'unknown flag: --description' after cobra falls back to printing the parent help, which does not make the real command obvious. The actual commands are set-description for body text and update for title, priority and track. Either add an edit alias or correct the directive text so agents do not burn a turn discovering it.
