Description

checkYoloWorkItemGuard (core/hooks/yolo_guard.go) gates Edit/Write on the session row active_feature_id (or sessionHasLinkedFeature on the same session). In nested/subagent sessions 'wipnote bug start' writes active_feature_id to a session row the PreToolUse hook does not resolve, so legitimate edits are false-blocked with 'An active work item is required'. hasAnyActiveWorkItem (the old fallback) is now unused dead code. Fix must avoid the old global-any-in-progress false-pass while restoring lineage/durable-state correctness, per the repo rule 'prefer file/branch/staged state over session state'.
