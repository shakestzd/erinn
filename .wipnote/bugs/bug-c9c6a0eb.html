Description

Discovered during Playwright QA: the project dashboard fires GET /api/terminal/sessions every 4s with no back-off, producing hundreds of 404 console errors (190+ in ~2min) on any /p// page. Root cause is client-side: the terminal routes ARE implemented (cmd/wipnote/serve.go:150-155 -> handleTerminalSessions in terminal_handlers.go) but gated behind os.Getenv WIPNOTE_TERMINAL == 1, so they 404 when unset. A startup probe probeTerminalFeature (dashboard/js/app.js:3108) already detects absence and hides the button, but the separate liveness setInterval at app.js:3849-3859 polls blindly and swallows the error in an empty .catch(). Fix (client): have the probe record a terminalFeatureAvailable flag (false on 404) and guard the interval body so the poll stops once the feature is known absent. Server route is correct; do not change it.
