Headless flows have no API-key auth path, which --bare will require when it becomes the -p default

Todo Medium Priority

Part Of:

  • trk-1db7bf72

Relates To:

  • Deprecate the plan-review chat backend

Description

Claude Code docs state --bare will become the default for -p in a future release. --bare strictly disables OAuth and keychain reads: auth becomes ANTHROPIC_API_KEY or apiKeyHelper only. wipnote has no ANTHROPIC_API_KEY wiring for its headless flows (compliance_auto.go, plan/planchat/backend.go), so when the default flips those flows lose authentication, not just discovery. Adding --bare proactively today would cause that breakage immediately for subscription/OAuth users, which is why bug-48b023e5 deliberately did not. The real work is an auth path for headless invocations. No opt-out flag exists, so pinning current behaviour is not available.
