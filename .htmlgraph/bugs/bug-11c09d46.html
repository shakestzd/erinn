Description

Root cause of bug-06e6eca3 (slash commands don't autocomplete in Codex TUI). Codex does not use slash commands — its interactive plugin capability is skill mentions via $skill-name. Discovery happens via .codex-plugin/plugin.json's 'skills' field pointing at a skills/ directory of SKILL.md files. Our generator writes plugin.json without the 'skills' field, so Codex never sees our 8 skills (deploy, plan, execute, diagnose, code-quality-skill, agent-context, orchestrator-directives-skill, strategic-planning) even though they're correctly structured and shipped. Verified by inspecting ~/.codex/plugins/cache/openai-curated/github/.../.codex-plugin/plugin.json (line 22: `"skills": "./skills/"`). Our equivalent file lacks that field entirely. Fix: 1. Add 'skills: ./skills/' to the codex target's plugin.json emission in packages/plugin-core/manifest.json (source of truth) so internal/pluginbuild/codex.go writes the field into the generated plugin.json. 2. Optionally: add [plugins.'htmlgraph@htmlgraph'] enabled = true to ~/.codex/config.toml during htmlgraph codex --init / --dev (mirror how openai-curated github gets enabled). 3. Document in README: Codex users type $htmlgraph or $ in the TUI, not /htmlgraph:command. The commands/ dir is inert for Codex (Claude Code-only). Open question per researcher: may need to verify skills-only declaration is sufficient to trigger discovery, or if enabled=true is also required. Test empirically.
