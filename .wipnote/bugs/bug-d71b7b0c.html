ingest-commits linking regex is stricter than the commit convention agents actually produce

Todo Medium Priority

Part Of:

  • trk-08dcbb33

Description

wipnote's commit-to-work-item linking requires a parenthesized ID like (bug-xxxxxxxx) or a closing keyword such as fixes/closes/resolves. Agents and tooling in this session routinely produce commit messages carrying the bare ID on its own line, which the regex does not match — so git_commits gets zero rows for that commit and the completion provenance gate refuses, forcing --accepted-advisory or a manual link-commit. This happened repeatedly across many agents tonight and is the practical cause of most manual link-commit calls. Either loosen the regex to accept a bare work-item ID token, or emit the parenthesized form by default in whatever generates commit messages. Related to but distinct from bug-6bfec440, which is about subagent commits not being ingested in real time; this one is about the message format itself failing to match.
