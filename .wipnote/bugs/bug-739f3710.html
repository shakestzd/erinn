ReadSubagentHint returns the most recently started subagent, not the caller

Todo High Priority

Part Of:

  • trk-c4615ad2

Relates To:

  • WIPNOTE_AGENT_ID not propagated to dispatched subagents, collapsing every claim to __root__

Description

The subagent hint fallback globs every hint file under the session hint directory and returns whichever has the latest StartedAt timestamp. That is the most recently started subagent in the session, not the one asking. Under concurrent dispatch, which is this project's normal mode, it hands the wrong identity to whoever calls it. This is tier 3 of resolveAgentID, so it only fires when the CloudEvent AgentID and the environment variable are both absent — but that is exactly the path a plain CLI invocation takes, and it means adding this same fallback chain to the claim-write path would not fix concurrent claims, it would silently attribute them to the wrong agent. A caller-scoped read is not possible from a plain CLI process with no event to say who it is, so the fix has to come from the environment being seeded correctly rather than from a better guess at read time.
