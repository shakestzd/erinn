claim conflict detection relies on SQLite's write lock rather than a UNIQUE constraint

Todo Medium Priority

Part Of:

Description

core/db/claim_repo.go ClaimItem detects multi-agent claim conflicts by relying on SQLite serialising concurrent INSERTs across processes. The claims table has only non-unique indexes — no UNIQUE constraint enforces the invariant at the schema level, so correctness rests entirely on the single-writer lock rather than on the data model. Two consequences: the guarantee is invisible to anyone reading the schema, and it would silently disappear under any storage change. Add a UNIQUE constraint expressing the actual invariant, which makes the behaviour explicit and robust regardless of backend. Note the codebase already has a non-SQLite locking primitive for this shape of problem in core/daemon's O_EXCL writer lease.
