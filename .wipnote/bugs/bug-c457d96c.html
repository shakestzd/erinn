go1.26 gofmt rewrote apostrophes in doc comments, corrupting five explanations

In Progress Medium Priority

Description

The formatting sweep applied go1.26 gofmt, which normalises straight apostrophes into typographic quotes inside doc comments. Five files were affected and in every case the apostrophes were the SUBJECT of the comment rather than incidental punctuation. Four comments explained that a column stores the empty string rather than null — written as two apostrophes — and now display a single typographic character that is neither, in code paths where the empty-versus-null distinction has previously caused real defects and where these comments exist specifically to stop that recurring. The fifth documents the harness delimiter for multiline literal strings, three apostrophes, which is the entire subject of the function and is now unreadable. No behaviour changed and the tree builds clean; the damage is purely to explanations, which makes it the same class as the misleading-documentation findings recorded earlier — a comment that asserts something untrue — except introduced by an automated tool rather than by drift. Restore the five comments, using backticks or a spelled-out description so a future formatter cannot mangle them again. Then decide whether this formatter should be run on this codebase at all without a post-pass that rejects character substitutions inside comments.
