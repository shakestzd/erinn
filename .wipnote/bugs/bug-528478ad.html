Dashboard project-scoped mutation routes use read-only DB: approve/finalize 500 'attempt to write a readonly database'

Todo High Priority

Part Of:

  • trk-13e39042

Description

Confirmed in production on v0.61.1 (user probe): POST /p//api/plans//feedback returns 500 'storing feedback: ... attempt to write a readonly database (8)'. The multi-project hub opens project DBs read-only (format string: open database (read-only)) and the per-project mux wires plan mutation handlers (feedback POST, finalize, chat, delete) to that read-only connection — the api_plans.go comment near line 777 promises these run on a dedicated writable handle, but that wiring only exists for root-scoped routes, and in 0.61.1 even the cwd project is served as a read-only /p// child with NO root-scoped plan routes at all. Net effect: every dashboard Approve click 500s, nothing persists to plan_feedback or YAML, and Finalize correctly reports nothing approved. THIS was the true root cause of the user-reported finalize failures (bug-eca8141d treated a secondary path). Fix: per-project mux must route mutation endpoints through a writable connection for the project (mirror root wiring; see buildSingleProjectMux factory from feat-79fd74ba and serve.go ~140 read-only/writable split). Add a regression test: POST feedback via /p// route persists a row.
