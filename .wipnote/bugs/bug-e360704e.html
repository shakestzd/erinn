Test-fixture completion intent leaked into the production commit outbox

Todo High Priority

Part Of:

Description

The pending outbox holds an intent to commit a feature HTML file that does not exist in the repository, any worktree, or any reachable scratch space, for a work item id no agent in the session ever created deliberately. It was enqueued during the exact window a test suite was running completion-path tests against fixtures, and its recorded repo root is the real repository. The likely mechanism: the completion path enqueues its commit intent using a repo root resolved from the environment — project-dir variable or cwd walk-up — rather than from the store the completed item actually lives in, so a fixture completion inside a temp directory writes a poison intent into the real per-user outbox. Consequence today is bounded noise: the intent fails on every flush and will eventually dead-letter. But the same leak with a colliding path would let a test commit a fixture artifact into the real repository. Fix by deriving the enqueued repo root from the artifact's own resolved store path, and add a test that completes a fixture item and asserts the production outbox is untouched. Verify the hypothesis by matching the ghost id against fixture ids the rollup and transactional-complete tests generate.
