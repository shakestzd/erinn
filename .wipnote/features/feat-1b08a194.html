Description

Sessions are the one node type work items link to whose lifecycle is ephemeral: raw events are gitignored, archiving tar-gzips them into an equally untracked graveyard, and nothing durable remains — which is why canonical HTML declares edges to 156 session targets of which 3 resolve. Fix the cause: a canonical git-tracked sessions ledger HTML file following the architecture-cards table pattern, fragment-addressable by session id. REVISED PER DESIGN REVIEW: the row is created at SESSION START, not archive time, mirroring the claim ledger exactly — open row at birth, enriched at death. Start writes id, harness, project and start time; session end closes the row with an end time; archive enriches it with distilled totals and the archive path if cheaply available. Root sessions only — synthetic per-subagent ids must not each get a row or the ledger fills with stubs, and the measured dangling targets are all root-session UUIDs. Start-time creation means an implemented-in edge written at completion never targets anything undurable even briefly, a session that dies unarchived still has its row, and the ledger — not the derived sessions table — becomes the validity authority the reindex gate consults, for live sessions as well as dead ones. The write costs are absorbed by existing machinery: once-per-session lock-and-append on the start hook, and the deferred commit-queue with per-path coalescing already handles a git-tracked file dirtied mid-session for the claim ledger. Edges keep their existing target ids; nothing rewrites old HTML. BACKFILL: the archive holds tarballs back to May, so most of the 153 dangling targets can be reconstructed — id and end time from the tarball at minimum. Tombstones remain only for pre-ledger sessions with no surviving archive. Open decision: one file with stable fragment urls versus sharding for worktree conflict avoidance — session starts are far rarer than claims, so one file is likely fine, but choose deliberately. Sequencing: after the in-flight edge-contract work, same gate and reindex region. Acceptance Criteria A session started after this lands has a canonical row before any edge can target it. The reindex gate resolves session targets from the ledger, not the derived table. Backfill reconstructs rows for archived sessions. Root sessions only. Survives a fresh clone.
