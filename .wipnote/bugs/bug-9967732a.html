Description

A flush reported committed seven, failed zero, dead-lettered zero, while leaving the architecture ledger modified and uncommitted in the working tree; it required a manual explicit add and commit afterwards. Either the flush's success accounting does not verify the tree state it claims to have produced, or the coalescing dropped a path silently. This matters because the deferred artifact policy makes flush the integrity point for everything between an arch-card write and its commit — a flush that says done while leaving work uncommitted is exactly the window in which a concurrent reset destroys unfushed writes, which happened tonight. Reproduce with a queue containing an architecture-ledger intent plus others, and make flush either commit what it claims or report what it skipped.
