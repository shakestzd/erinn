wipnote check runs its Go gates in a directory that does not exist

Todo Medium Priority

Part Of:

  • trk-08dcbb33

Description

The Go gate runner resolves its working directory to a packages subdirectory named go beneath the repository root, and checks for a module file there. That path does not exist in this repository — the packages directory contains only the plugin-core tree, and the Go modules live at the root and in four nested directories. Consequence: a bare invocation of the check command reports failure for build, vet and test unconditionally, regardless of the tree's actual state. It is not detecting a problem; it is failing to find anything to run. The guard-profile path used during work-item completion resolves correctly and is unaffected, which is why this has gone unnoticed — the failing surface is the one a human types, and the passing surface is the one automation uses. Fix by resolving the module set the way the rest of the tooling does, covering the root plus the nested modules, rather than assuming a single packaged Go directory. Note the failure shape: a gate that always fails carries no information, which trains people to ignore it, the same erosion as a test that fails by calendar.
