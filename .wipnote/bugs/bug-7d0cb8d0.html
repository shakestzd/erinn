Devcontainer pins a Go version now behind the language directive

Todo Low Priority

Part Of:

Description

The development container image is pinned to a Go 1.24 base and its readme documents that version in two places, while the module language directive has moved to 1.25 following a dependency bump. Nothing breaks today because the toolchain setting defaults to automatic and will fetch the newer version on first use inside the container, so this is staleness rather than a failure. It is worth correcting because the pin and the prose now disagree with the module, and the next person reading either will be misinformed in a way nothing surfaces — the same shape as documentation that asserts behaviour the code does not have. Update the base image tag and both readme references. Build workflows are unaffected: they read the version from the module file and hardcode nothing.
