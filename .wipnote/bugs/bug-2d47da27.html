Ledger artifacts fail the incremental node scan, freezing last-indexed-commit

Todo High Priority

Part Of:

  • trk-2c55adea

Description

The incremental reindex parses every changed HTML file under the store as a work-item node and counts a parse failure as an error. Four canonical artifacts are tables rather than nodes and therefore fail that parse on every run: the architecture ledger, a claims shard, the sessions ledger, and the gate ledger. The resulting non-zero error count suppresses the last-indexed-commit write, so the incremental pass never advances its bookmark. Confirmed live: the bookmark is frozen dozens of commits behind head. The architecture ledger has done this since it existed, so the freeze is long-standing and each new ledger makes it worse — three of the four artifacts arrived tonight. Fix by excluding table-shaped artifacts from the node scan alongside the existing recap exclusion, and add a test that a store containing every artifact type still advances the bookmark. Worth noting the failure shape: the error is printed on every run and was visible the whole time, but because the only consequence is a bookmark that quietly stops moving, nothing ever escalated it.
