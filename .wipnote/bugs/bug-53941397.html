api_request implies success is an inference, not a documented contract

Done Medium Priority

Caused By:

  • otel success column not persisted on tool_result/tool_execution/api_request spans

Part Of:

  • trk-c4615ad2

Description

The log conversion hardcodes success true for api_request events, on the reasoning that failures are emitted as a separate api_error event so reaching api_request at all implies success. The doc audit finds this is plausible but nowhere stated. The api_request event carries no success, status or error attribute of any kind, and the documentation never says the two events are mutually exclusive. There is supportive precedent elsewhere in the same vendor's design, where a post-tool hook fires only after success and failures get a separate hook, but precedent is not a contract. The risk is asymmetric: if the assumption is ever wrong, every failed API request is silently recorded as a success, which inflates exactly the metric the derivation exists to produce. Mark the assumption explicitly at the code site, and make it a candidate for the population canary — a sudden appearance of api_error volume without a matching change in api_request success would falsify it.
