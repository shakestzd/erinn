Description

The transcript ingest parser tests construct every fixture by hand to match what the parser already expects, with none captured from or grounded in a real transcript. This is the same defect class as the adapter tests, on a different pipeline: a renamed or restructured field in a future harness release would silently zero out token and model attribution for every ingested session, with a fully green suite throughout. It feeds the same cost and token rollup, so it deserves the same remedy. The retired-harness parser has the identical shape but lower priority, since that format is frozen and cannot drift further — though a fixture that was always subtly wrong would still be invisible. Note the discriminator that makes this a defect here and not elsewhere: it applies where an external vendor owns the schema on the other side. Tests that construct fixtures for wipnote's own writer and parser are fine, because there is no upstream to drift out from under them.
