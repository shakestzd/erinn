reindexFeatureFiles spawns one git diff-tree per commit per feature, making first-run reindex take 10+ minutes

Todo High Priority

Part Of:

  • trk-08dcbb33

Description

expandCommitFiles in cmd/wipnote/reindex_files.go runs git diff-tree once per commit hash, and is called per FEATURE with that feature's commit list — so a commit linked to several work items is diff-tree'd once per item. A single diff-tree costs about 15ms, and after uncapping the trailer scan (bug-9577013c) attributed commits went from 1835 to 4181 across roughly 900 work items, producing tens of thousands of subprocess spawns plus 24000-plus individual upserts. Observed: a full reindex exceeding ten minutes where it previously took four. The cost is process creation, not git or SQLite. Fix by replacing the per-commit calls with a single 'git log --name-only' pass building a commit-to-files map in memory, then upserting in a batched transaction — the same approach already used to measure the linkage ceiling, which parsed 5179 commits in one pass. Note the high-water mark makes this a one-time cost, but every existing user pays it once on upgrade.
