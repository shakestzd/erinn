Description

Correct per-work-item attribution needs per-signal agent identity AND a durable record of which agent held which item when. Neither exists. Every claim-bearing table is single-mutable-slot current-state: active_work_items is INSERT OR REPLACE and holds 3 rows ever, claims has 58 rows all under __root__, and sessions.active_feature_id is wiped to empty on completion, precisely the event it would be needed for. DESIGN, researched: the ledger does NOT belong in SQLite (derived and deletable) and does NOT belong in the work item HTML — node fields are snapshot-not-log, and ClaimItemOrRenew fires on lease renewal, so per-item history would bloat every work item diff with heartbeat noise. The existing session events NDJSON is not a candidate either: despite hook comments calling it canonical, it is gitignored, so it does not survive a fresh clone. Recommendation is a new git-tracked append-only NDJSON ledger under the store, explicitly carved out of the gitignore rules that currently blanket-exclude session telemetry, one record per claim lifecycle event — claimed, released, completed, abandoned, expired — and NOT per heartbeat renewal. Fields: work_item_id, session_id, agent_id, event, timestamp. This is a new canonical artifact class alongside the HTML nodes, ingested by reindex into a new table the same way HTML is ingested today. On sessions.active_feature_id: leave the wipe alone. The field is correctly scoped as live state and is the wrong home for history regardless, being both derived and a single scalar incapable of holding more than one claim episode.

Acceptance Criteria

Ledger survives a full cache wipe and a fresh clone. Claim history is queryable by (session, agent, time) so a signal can be attributed to the claim active when it was emitted. Heartbeat renewals do not produce records.
