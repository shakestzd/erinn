Description

core/workitem/htmlwriter.go edgeData carries only TargetID, Href, Relationship, Label, HasSince and Since — there is no properties field, and the rendered nav emits only data-edge-type. So models.Edge.Properties persists ONLY via the SQLite dual-write in Collection.AddEdge and is lost on any rebuild from HTML. Consequences: the dedup heuristic's similarity_score and needs-triage-dup tag do not survive a rebuild, compounding bug-b4458e51; the origin stamps added under bug-d0489158 and bug-f55532ba are SQLite-only; and any future edge attribute is too. This is a hard blocker for putting provenance or a commit-SHA anchor on edges, since neither would survive a reindex. Fix by extending edgeData and the edge nav markup to carry properties, e.g. as data-edge-* attributes or a serialised payload, and teaching the reindex parser to read them back.
