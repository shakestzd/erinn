Two independent benchmark programs parsing the canonical HTML with core/htmlparse counted 3178 edges (excluding the stale pre-merge-backup directory) and 3211 (including it), while graph_edges held 3096 to 3099 at the same time. The roughly 80-edge gap excluding the backup directory is unexplained. This matters because TestReindex_EdgeCensusIdenticalOnRebuildFromUnchangedHTML now asserts a rebuild is lossless, and a standing 2.5 percent discrepancy between canonical HTML and the index suggests that invariant may hold only for the synthetic fixture and not for the live corpus. Reconcile edge-by-edge and either fix the loss or document why those edges are legitimately excluded.
