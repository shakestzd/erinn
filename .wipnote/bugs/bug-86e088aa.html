Description

The project's debugging rules state that session state is fine for attribution and telemetry but not for gates, because gates must be reproducible across session restarts. The yolo-mode guards break this: hasRecentResearch, hasRecentWebResearch, hasRecentTestRun, hasRecentDiffReview and the UI validation guard all block tool calls based on COUNT queries over agent_events scoped to the current session plus a 24-hour fallback window. A restarted session therefore sees a different gate outcome for identical work, and the enforcement silently weakens whenever event history is absent. Either derive these signals from a reproducible source, or document the exception explicitly. Flagged during the telemetry value audit; independent of the retention question.
