DIAGNOSED 2026-06-10 (researcher, confidence 8/10). NOT signature drift — ComputeSignature only hashes immutable DB-row fields and round-trips cleanly. Real root cause: session-identity race across separate CLI subprocesses. (1) Each orchestrator Bash call lacks WIPNOTE_SESSION_ID so EnvSessionID falls back to .wipnote/.active-session, which concurrent agents' SessionStart hooks overwrite — check --gate resolves session A, feature complete resolves session B. (2) check --gate stores work_item_id EMPTY because activeWorkItemForGate(sessionA) finds no attribution, so LatestPassingGateRecordForWorkItem (the bug-35857288 cross-session fallback queried with the explicit CLI work-item id) cannot match the record either. Chained '&&' works because one process tree = one session resolution, no hook fires between. FIX: make gate records always carry a non-empty work_item_id — add optional --work-item flag to wipnote check --gate (validate the id exists); when absent keep activeWorkItemForGate but fall back to most-recent in-progress item; completion path unchanged, HEAD re-gate semantics preserved. Confirming experiment: run check --gate then sqlite3 query gate_records for empty work_item_id; compare session ids printed by two separate invocations. Key sites: cmd/wipnote/check.go ~67, check_gate_support.go runSessionGate/persistGateRecord/validateCompletionGateRecord ~267-592, core/hooks/runner.go EnvSessionID ~305.
