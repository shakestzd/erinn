Stabilize flaky timing-sensitive tests: TestSQLiteContentionStress & TestIdleReaperKillsStaleChild cause spurious CI/deploy failures

Todo Medium Priority

Part Of:

  • trk-43648254

Description

Two timing-sensitive Go tests intermittently fail under CI-runner / concurrent load and produce spurious red CI and deploy failures (observed repeatedly across the 0.60.9-0.60.15 release run): (1) TestSQLiteContentionStress (cmd/wipnote) fails with first-party SQLITE_BUSY under concurrent load (e.g. parallel goreleaser snapshot or two go test runs); passes isolated with -count=3. (2) TestIdleReaperKillsStaleChild (internal/childproc) fails 'child was not reaped after idle; children=1' under runner load (idle-reaper timeout race); passes on re-run. Neither is a real regression. Goal: make them deterministic/robust under load — e.g. inject/relax timeouts via a test clock or generous CI-tunable deadlines, reduce shared-resource contention, or gate the stress test behind a serial/-tagged lane so it never races other packages. Acceptance: 3 consecutive full 'go test ./...' runs under load with zero first-party flakes.
