Done Medium Priority

Part Of:

Description

Follow-on to spk-3375caf7, which established that caused_by between work items is unverifiable by construction because both endpoints are project-management objects, and that wipnote has no behaviour node type while tests already serve that role. Three design questions: rename the work-item edge vocabulary to stop implying causality it cannot carry; design behaviour edges anchored to something runnable; make tests first-class nodes. Plus one architectural precondition: determine whether graph_edges is genuinely derived from HTML as the stated invariant requires, or whether some edges are born in SQLite and unrecoverable on rebuild. At least one such case is already known (plan implemented_in).
