Description

Codex sends per-subagent identity and wipnote discards it. Verified against the authoritative generated JSON Schema in the openai/codex repository, which is ground truth because it is generated from the Rust wire types: agent_id and agent_type are declared on PreToolUse, PostToolUse, PermissionRequest, SubagentStart and SubagentStop. Note the prose documentation is inconsistent with its own schema, listing those fields only for the subagent lifecycle events — trust the schema. Codex also supports the same permissionDecision allow plus updatedInput output shape as Claude, and its shell tool is literally named Bash, the same string, so the existing rewrite mechanics apply unchanged. What blocks it today: the codexPayload struct carries no agent id field at all, and parseCodexEvent hardcodes the event agent id to a static per-harness constant for every event, silently throwing away the real value. Separately the plugin manifest registers the subagent lifecycle events for the Claude target only, so Codex is not wired to receive events it already dispatches. Three changes: add the fields to the payload struct and parser, register a Codex adapter against the existing agent identity seam, and add the subagent events to the Codex target in the manifest.
