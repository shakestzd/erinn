Description

Launch chooser label shows real Claude UUID (019ee378) but the resume action passes the wipnote OTel collector session ID (019ee144, 28-char hex) to 'claude --resume', which Claude Code does not recognize -> 'No sessions match'. Root cause: launcher stamps the OTel session ID into WIPNOTE_SESSION_ID (claude_env.go:61-63), which is also wipnote current-session identity used by feature-start attribution (runner.go:328); loadContinueSessionContext then resolves the work item session to the OTel ID and sets TranscriptResumeID to it (launcher_continue.go:105-111). Fix A: separate env var for OTel session id. Fix B: reject non-Claude-UUID TranscriptResumeID before --resume.
