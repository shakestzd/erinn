Description

Remove all per-project persistent SQLite files and cache lifecycle while retaining SQLite solely for process-local in-memory query acceleration where benchmarks justify it. Canonical HTML, ledgers, NDJSON, and Git-derived state must be sufficient for correctness and rebuilds. Acceptance Criteria No project open, hook, CLI, daemon, dashboard, or telemetry path creates or requires a project SQLite file, WAL, or SHM; persisted SQLite migrations/reindex/checkpoint/cache eviction are gone; deleting runtime caches cannot lose canonical state; in-memory SQLite use is explicitly isolated and process-ephemeral. Test Strategy Characterization parity for CLI/API/gates/lineage/telemetry; project tree and cache-root assertions prove no DB/WAL/SHM creation; rebuild tests start from canonical artifacts only; benchmarks compare retained in-memory SQLite paths with native Go alternatives.
