Description

Post feat-fc3cc9e0 the projection is rebuilt per process from canonical artifacts. reindexClaimEpisodes projects claim_episodes and reindexActiveWorkItems projects active_work_items, but NOTHING populates the claims table. db.LiveCollision -> DetectCollaboration -> ListClaimsForWorkItem reads claims, and SessionLivenessByHeartbeat reads claims.last_heartbeat_at, so both see zero rows in any hydrated projection. Consequences: wipnote continue never detects that a work item is still live in another session, and claim-collision refusal on feature start is inert. Fails OPEN so it is not a deploy blocker, unlike bug-369da005. Blocked on a design decision: an open claim episode carries StartedAt but no heartbeat, and defaultLivenessStalenessSeconds is 120s, so StartedAt cannot stand in for last_heartbeat_at. Needs a canonical liveness signal (a heartbeat marker, or deriving liveness from the session ledger row still being open) before claims can be hydrated honestly.
