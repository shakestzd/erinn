Description

Every attribution finding in this investigation came from Claude Code, because the live telemetry index is roughly 100 percent claude_code traffic — 39574 of 39859 rows. That is sampling bias, not a design decision. wipnote ships one plugin to Claude Code, Codex CLI and Antigravity from a single source, so a fix that only ever receives real agent identity on Claude would leave Codex-dispatched work collapsing to __root__ permanently, with nothing in the data indicating why the two harnesses disagree. The architectural split: identity acquisition is necessarily harness-specific, since Claude offers a documented agent id on hook payloads plus an input-rewrite mechanism that other harnesses may not have, while everything downstream — the claim write path, the durable ledger, the attribution model — must be harness-neutral. Put acquisition behind a seam following the existing per-harness adapter pattern rather than inlining Claude specifics into the shared hook path. Requirement: when a harness cannot supply an identity, the resulting fallback must be explicitly distinguishable from a genuine root agent. Those are different facts and must not be indistinguishable in the data.
