codex.go (launchCodexDefault) and gemini.go (launchGeminiDefault) create managed worktrees from HEAD via applyLaunchPlan but have no CarryUncommittedChanges call, so uncommitted main work is left behind — same bug fixed for yolo (bug-bcf8a311) and claude (bug-c3483435). Wire both launchers to the shared emitWorktreeCarryoverMessage helper (worktree_helpers.go) + resolveManagedWorktree*Status, mirroring claude. Follow-up to the claude carryover fix.
