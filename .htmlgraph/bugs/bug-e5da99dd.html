UserPromptSubmit dumps full attribution block on every turn — should be SessionStart-only

Done High Priority

Caused By:

  • bug-a87c8c04

Part Of:

  • trk-a7ee6791

Description

internal/hooks/user_prompt.go's buildAttributionGuidance emits the full block (open work items roster, CLI quick reference, required flags) as additionalContext on EVERY UserPromptSubmit. Claude Code displays additionalContext verbatim as a banner under each user message, so the orchestrator's chat gets flooded with ~20 lines per turn of mostly-static reference material. Fix: split the content by cadence. SessionStart (once per session): - Open work items roster - htmlgraph CLI quick reference - Required flags reminder - General orchestrator intro (already present) UserPromptSubmit (every turn, goal: terse): - Turn-specific classification signals (Exploration detected, CodeChanges detected, Git detected) — keep - ACTIVE work item one-liner: 'ACTIVE: — ' when a work item is active, omit when none - Nothing else Implementation: - In user_prompt.go, stop calling buildAttributionGuidance; replace with a shorter 'active work item only' formatter - In session_start.go, inject the full attribution block (reuse buildAttributionGuidance) - Move compactCLIRef const into session_start.go (or a shared prompts helper) Test: run a Codex/Claude session, confirm the first turn's additionalContext is ~1-2 lines (ACTIVE + any classification signal), not the full 20-line block.
