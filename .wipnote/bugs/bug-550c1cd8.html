Gate decisions depend on tables with no canonical source

Todo High Priority

Part Of:

  • trk-2c55adea

Description

Classifying every table by what a fresh clone plus reindex could reconstruct leaves two that affect decisions and cannot be rebuilt. Gate records, sixty-nine rows, exist nowhere but the derived index — nothing writes them to the canonical store — yet the completion gate consults them through a fallback window to decide whether a work item may complete. The index lives in the operating system's cache directory, which the system is entitled to purge, so a purge silently changes whether completions are permitted. Agent events, ten thousand rows, are read by five yolo guards that block tool calls and by the advisory that injects context mid-turn; they are rebuildable on the same machine from a gitignored file but not across a clone. Everything else that cannot be rebuilt is informational — telemetry, transcripts, dashboard history — and should stay that way, because high-volume machine output does not belong in git. The gap therefore does not close by making everything canonical. It closes one of two ways, and the choice should be deliberate: give these two a canonical or at least git-tracked backing, or accept they are ephemeral and make every gate that reads them treat absence as an explicit, stated condition rather than silently behaving differently. Same root as the existing finding that the guards violate the project's own rule about gates being reproducible across session restarts.
