Description

The board's feature query self-joins the features table on a track id — matching a track identifier against the features table's own primary key. Track ids and work item ids come from different namespaces and never collide, so the joined title is empty for every row in production today. The column is selected and returned to the client, which renders nothing rather than erroring, so the failure is invisible. Found incidentally while enumerating dashboard joins for the graph-index scoping. Pre-existing and unrelated to that proposal. Fix by joining the tracks table instead, or resolve the title in memory. Worth noting the shape: a join that cannot ever match is indistinguishable at runtime from one that matches nothing yet, which is why it survived.
