Description

CONFIRMED ROOT CAUSE, and it is NOT the telemetry attribution defect — it is a separate priority inversion. Feature-file attribution never reads the active work items table at all. The tool-use context resolver composes two sources in Go: the session-wide active feature column, and the per-agent claims row. The composition assigns the session-wide value first and only falls back to the per-agent claim when that is empty. So the shared root value wins unconditionally regardless of which agent is asking, which is backwards — it is root-first with agent-specific as fallback, the inverse of what correct attribution requires. The write side already encodes the right intent: the function controlling who may write the session-wide column restricts it to root and codex only, with a comment stating that subagents rely on per-agent claims for their own attribution. The read side never conditions on the agent at all. The correct pattern also already exists a few lines away in the pre-tool-use guard, which uses the agent-scoped value when the event is a subagent — but it was never applied where the shared context field itself is computed, so every other consumer inherits the wrong value. Blast radius is larger than feature files: it also feeds git-commit attribution, session activity logging, the always-on work-item guard, and the yolo guard. The identity propagation fix does not resolve this — that corrected the claims write path, while this is a read-ordering defect that fires regardless. Recommended shape: when the event is from a subagent, prefer the agent's own claim and fall back to the session-wide value only when the agent has no claim. Acceptance Criteria A subagent's tool calls attribute to that subagent's own claimed work item, not to whatever the root session last claimed. Verified with two concurrent agents holding distinct claims.
