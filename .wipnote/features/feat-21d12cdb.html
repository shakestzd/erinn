Description

Durable record of which agent held which work item when — the missing half of correct attribution. Per-signal agent identity now flows; nothing records the intervals to join it against, because every claim-bearing table is single-mutable-slot current state. STORAGE: a table in an HTML file, following the architecture-cards precedent — one table, one row per record, data attributes plus field cells, parsed and ingested by the existing machinery. Sharded one file per ROOT session under a dedicated directory in the store, NOT under the session telemetry directory, which is gitignored and would not survive a fresh clone. Sharding eliminates cross-session and cross-worktree merge conflicts, which a single shared file would generate on every worktree merge. Root-session rather than per-subagent granularity keeps the file count to one per session instead of one per agent, and intra-session contention is handled by the existing lock. ROW SHAPE: one row per claim EPISODE rather than per event, carrying work item, session, agent, start, end and outcome. A time-bounded activity is one row; an event log would need two records and a join. Heartbeat renewals produce no rows. WRITE PATH: reuse the canonical HTML lock verbatim — in-process mutex keyed by path, blocking cross-process file lock on a sidecar, atomic temp-then-rename — but do NOT reuse the arch-card write body, which parses and reserializes every row. Under the same lock, append the row with a trailing-byte check following the existing outbox append guard, so a torn prior write cannot merge into the new row. Constant write cost instead of linear. File-level append-only is not required: git history is the append-only log, as it already is for work items and cards. ARCHIVE: a compaction step rolls closed sessions' files into a single archive file in the same directory, bounding file growth while keeping the working set small. NOT the write daemon: its applier has no file-write op and no writable-file handle, and routing through it would blur the canonical-versus-derived boundary. Acceptance Criteria Claim history survives a cache wipe and a fresh clone. A signal from a known agent at a known time resolves to the work item that agent actually held. Heartbeat renewals produce no rows. Two concurrent agents in one session both land their rows. Two sessions in separate worktrees merge without conflict. Each episode is addressable by fragment. Archived sessions remain queryable.
