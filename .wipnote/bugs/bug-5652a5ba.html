Description

The dedicated tool_use_id column on otel_signals is populated on ZERO of 39724 rows, while json_extract of attrs_json for tool_use_id returns a value on 19768 rows, about 50 percent. The data arrives from the harness and reaches the row as raw JSON, but the column extraction never fires. This is the fourth instance this session of the same pattern: a field that exists in the schema or model, is fed by real upstream data, and is silently dropped at a write or parse boundary. The prior three were plan edges never scanned by reindexEdges, edge properties never rendered, and node Properties never rendered or parsed. Practical impact is that joining otel_signals to tool_calls on tool_use_id is impossible via the column, and doing it through attrs_json recovers only 891 rows because tool_calls is itself a thin table of 675 rows. Fix the extraction and add an assertion that the column is populated wherever the JSON carries it.
