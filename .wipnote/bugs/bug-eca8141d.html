Description

User-hit on v0.61.0 (Nipesa desktop plan): UI shows 8/8 slices approved but Finalize rejects 'not all sections approved'. Root cause: IsPlanFullyApproved/GetSliceApprovals gate on plan_feedback rows in the derived per-user SQLite cache, while the review rail + slice APPROVED chips read canonical plan YAML. Reindex/first-run rebuild does NOT replay plan_feedback (no reindex code references the table), so any cache rebuild (e.g. after upgrade) wipes approvals and strands every reviewed-but-unfinalized plan: GetSliceApprovals returns empty, legacy design/outline fallback also finds nothing, finalize blocked. FIX: make finalize gating canonical-first — if plan YAML slices carry approved status, accept that when plan_feedback has no rows (or better: replay slice approvals into plan_feedback during reindex from the canonical store, mirroring the dual-write fix from bug-3e524d0f). Workaround: re-approve each slice in the dashboard to repopulate rows. Related: bug-9f753d25 (slices-only unification, shipped in v0.61.0), bug-3e524d0f, bug-4b399212. Key sites: core/db/plan_feedback.go GetSliceApprovals ~198 + IsPlanFullyApproved ~106, cmd/wipnote/api_plans.go planFinalizeHandler ~395.
