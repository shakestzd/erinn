Description

Telemetry lands as NDJSON sharded per session and is then ingested into SQLite, costing 377 seconds of every rebuild, 55MB of index, and an entire schema-drift surface that failed silently for months. Nothing behavioural reads the ingested table — only dashboard aggregation does, and the guards that matter read a different table scoped to a single session, where the filename already serves as the index. The question is whether an engine can provide SQL aggregation over the canonical files in place, removing the ingestion step and the second copy together. DuckDB is the obvious candidate and fits the shape exactly, but its Go driver wraps a C++ engine and requires cgo, while wipnote deliberately uses a pure-Go SQLite driver so the binary cross-compiles without a C toolchain. Establish whether a Go-friendly alternative exists, or whether the cgo cost is the real price of this capability.
