Description

wipnote feature start regenerates the parent track's HTML to link the new feature, but neither the start nor the complete artifact-commit path stages it, so the track file sits dirty until someone commits it by hand. Observed during feat-f01b523e, where trk-08dcbb33.html had to be committed separately. Consequence: the canonical track record silently drifts from the work items it contains, and in a multi-agent session the dirty file also trips other agents' uncommitted-source gates, producing spurious --allow-dirty usage. Include regenerated parent-track HTML in the same artifact commit as the work item that triggered it.
