DesignApproved

Problem

BuilderIO's /visual-plan and /visual-recap give agents rich, reviewable visual artifacts (block-structured plans; recaps that turn a diff into an interactive summary), but they depend on a hosted third-party MCP (Agent-Native Plans). wipnote already owns equivalent rendering surfaces (plantmpl, the serve dashboard, lineage) yet exposes plans as a single layout, has no recap surface at all, and emits lineage as text only. We want the same visual ergonomics, natively and local-first, with recap grounded in wipnote's unique causal lineage.

Goals

  1. Ship a first-class lineage-grounded recap: `wipnote recap` writes a committed recap-*.html accepting work-item / git-range / session inputs
  2. Enrich plans with structured visual blocks (data-model, api-endpoint, file-tree, before/after HTML wireframes) via one shared renderer
  3. Surface recaps and enriched plans in the existing dashboard with no new frontend dependencies
  4. Expose /visual-recap and /visual-plan skills portable across Claude/Codex/Gemini via build-ports
  5. Keep everything local-first: no hosted MCP, HTML stays canonical

Constraints

  • Local-first: no hosted Agent-Native Plans MCP dependency; no data leaves .wipnote/
  • Single-source-of-truth: HTML is generated/canonical; never hand-edit recap-*.html or plan-*.html
  • Reuse existing D3 v7 + vanilla JS + Prism; no new frontend frameworks
  • Before/after wireframes are plain HTML/CSS design tokens; no Playwright/screenshots/headless
  • Plan-schema additions must be additive-optional (existing v3 plans validate unchanged)
  • Skills build across all 3 harnesses via `wipnote plugin build-ports`
  • Never author or overwrite project AGENTS.md/CLAUDE.md (plugin/project boundary)

#1 Recap collector core — resolve work-item / git-range / session into grounded diff data New internal/recap package. L Med Complex Promoted Approved 1 Q
What

New internal/recap package. A collector that, given one of three inputs (work-item id feat/bug/spike, a git range commit/branch/PR, or a session id), mechanically resolves the set of commits + changed files + per-file diff hunks. For work-item and session inputs, walk the existing lineage graph (extract the BFS walk from cmd/wipnote/lineage.go into internal/lineage so both the CLI and the collector consume it — DRY). Emit a typed RecapData struct (outcome facts, file list with change flags, hunks, lineage chain, provenance).

Why

Recap's differentiator is causal grounding: every fact derived from real commits/files, never inferred. This is the data layer the whole feature stands on.

Files
internal/recap/collect.go, internal/recap/types.go, internal/lineage/walk.go, cmd/wipnote/lineage.go
Done when
  • Given a feat-id, collector returns the commits linked via lineage and the union of changed files with add/modify/delete flags
  • Given a git range (e.g. main..HEAD), collector returns the same RecapData shape with no work-item grounding
  • Given a session id, collector returns files/commits produced in that session
  • Lineage BFS walk is shared between cmd/wipnote/lineage.go and internal/recap (no duplicated traversal)
  • TestCollect consumes the shared internal/lineage walk — cmd/wipnote/lineage.go retains no private BFS copy (DRY enforced)
Decisions

Scope: internal/recap owns collection only (no rendering). Extract lineage BFS to internal/lineage to avoid a second traversal implementation. State: RecapData is in-memory, derived; the committed artifact (slice-3) is canonical. Grounded entirely in git + .wipnote/*.html, nothing external. Payload: RecapData{Outcome, Files[]{Path,Change,Hunks}, Commits[], LineageChain, Provenance}. Hunks carry before/after for the diff renderer. Rejected: parsing git diff text in the renderer (re-parse risk + couples layers); a recap-specific lineage walk separate from the CLI's (DRY violation, drift risk). Module: internal/recap and internal/lineage are ROOT-module packages (github.com/shakestzd/wipnote/internal/...). The BFS extraction is an intra-root-module refactor: move pure bfsWalk/forwardWalk/backwardWalk/annotateTimestamps + lineageNode types into internal/lineage; the cobra wiring (newLineageCmd, openReadOnlyDB, findWipnoteDir in cmd/wipnote/lineage.go) STAYS in cmd/ (import direction: internal must not import cmd). Verified extractable — BFS takes only *sql.DB (cmd/wipnote/lineage.go:294). Diff acquisition: shell out to git diff --unified=3 -- <file> and parse minimal unified-diff hunks (consistent with wipnote's existing git subprocess usage). No diff library added — none present in any of the 5 go.mod files; a hand-rolled go-diff dep is rejected as unnecessary.

What

Make recap artifacts first-class & discoverable. Add a recaps table (or a type='recap' extension of the artifact index) via a core/db migration; teach reindex.go to ingest .wipnote/recaps/*.html; add "recaps" to the directory lists in reindex and resolveItemHTMLPath (relevant.go) so wipnote find and wipnote relevant surface recaps; extend inferNodeTypeFromID with the recap- prefix; add wipnote recap list|show|delete subcommands for headless/CI use.

Why

Without this, recaps are committed but invisible to every SQLite-backed surface (find, relevant, list APIs, graph edges) and there is no CLI to inspect/clean them. DESIGN+FEASIBILITY both flagged this as a danger-level blocker.

Files
cmd/wipnote/reindex.go, cmd/wipnote/relevant.go, cmd/wipnote/recap.go, core/db/migrations.go, core/db/migrations_test.go
Done when
  • reindex ingests .wipnote/recaps/*.html into the recaps table/index
  • `wipnote find` and `wipnote relevant` return recap artifacts
  • `wipnote recap list`, `wipnote recap show <id>`, `wipnote recap delete <id>` work headlessly
  • inferNodeTypeFromID maps the recap- prefix to a recap node type
  • the new core/db migration name is appended to BOTH hardcoded want-lists in migrations_test.go
Decisions

Scope: discoverability + lifecycle for the recap kind (the blocker the original plan missed). State: new core/db recaps table (derived read-index; HTML stays canonical). Migration HAZARD (project memory): adding a core/db migration breaks two hardcoded want-lists in migrations_test.go — appending the new name to both is a required done_when, not optional. Rejected: a filesystem-glob list endpoint (diverges from every other SQLite-backed list handler — DESIGN warn).
