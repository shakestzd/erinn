runSessionEnd in cmd/wipnote/session.go around lines 222-255: when apply.RouteSessionStatus returns false (daemon unreachable), the fallback calls dbpkg.UpdateSessionStatus against the throwaway in-memory projection returned by openDB, which is closed immediately afterwards. That update never reaches the canonical sessionledger store. The command reports success while the session stays open in the ledger forever. This is the write-lands-nowhere shape: the fallback compiles and returns no error because the handle is still a valid sql.DB, but it is ephemeral and process-local rather than durable.
