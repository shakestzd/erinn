reindex reports git failures as canonical artifact parse errors

Todo Medium Priority

Part Of:

  • trk-2c55adea

Description

reindexCommitTrailers failing with git exit status 128 — which happens whenever reindex runs outside a git repository, as most test fixtures do — is counted into errCount at reindex.go around line 168 and then reported to the user as N canonical artifact(s) failed to parse. It is not a parse failure and no artifact is involved. Found while diagnosing a vacuous sentinel test, where this message sent one investigator looking for a broken HTML fixture that was not the cause. The fixture did also have a genuine parse problem, which made the misleading message look corroborated. Any full reindex outside a git repo reports phantom artifact failures, so this is a plausible source of confusion in other fixtures too. Separate the git-derived pass errors from artifact parse errors in both the count and the message.
