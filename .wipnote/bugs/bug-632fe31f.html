Description

The Claude and Antigravity launchers both write the launch marker file that downstream hooks use to tell a launcher-started session from a bare one. The Codex launcher never calls it — verified by reading both Codex launcher files in full. It does set harness and project-directory environment variables on the child, but those are weaker signals: a variable lingering in a long-lived shell tab after its launcher died reads as permanently current, whereas the marker carries a process id and modification time and the existing liveness check already tests both against a freshness window. Consequence: a Codex session started by the launcher is today indistinguishable from a bare one, so any policy keyed on that marker would treat the happy path as unlaunched. The read side needs no change — the allowed-harness list already includes codex and the freshness check is already harness-neutral. The fix is a single call in the Codex launch path mirroring the two existing call sites. This blocks the daemon availability policy, which distinguishes launcher-started sessions from bare ones.
