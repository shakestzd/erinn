Blocked By:

Description

Real-user feedback from an external project running wipnote in YOLO mode (multi-slice plan execution). A subagent (Build qbank manifest, feat-ac3c1dfd) did its work inside the YOLO worktree, but the orchestrator expected the main checkout and hit 'Path confusion — the agent worked in this worktree, not the main checkout', then had to manually locate the correct path to run quality gates. Then wipnote feature complete refused with 'Commit the implementation first' even though the slice was committed (7d7b3bf), because uncommitted files existed in the worktree — suggesting gate/complete logic and the orchestrator disagree about which checkout is authoritative. User expectation: YOLO mode should isolate each unit of work on a dedicated per-track branch plus a corresponding worktree, and the surface where subagents operate should be explicit and consistent so the orchestrator, the gate/test runner, and feature-complete all target the SAME checkout. Symptoms to address: (1) ambiguity about whether subagents work in the track-branch worktree vs the main checkout; (2) gates/tests executed against the wrong directory; (3) feature complete's uncommitted-source check evaluating the wrong checkout or conflating worktree state. Likely needs a spike first to define the intended YOLO isolation model (per-track branch + worktree, working-dir contract surfaced to subagents) before implementing enforcement. Note: paths in the source transcript were host-absolute and are intentionally omitted here.
