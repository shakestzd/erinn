Description

Root cause of the whole track: nothing validates that a hook event name registered in the manifest actually exists in the target harness's event vocabulary. A wrong name fails silently and forever. Two instances already confirmed: Codex carries three phantom events, and the generated Antigravity hooks.json emits wrong event names (see arch card gemini-cli-sunset-antigravity-hook-bugs). parity_test.go checks commands/skills/agents exist in all trees but has no vocabulary for event-name validity. Add a per-harness allowlist to the port build and fail the build on an unknown name.
