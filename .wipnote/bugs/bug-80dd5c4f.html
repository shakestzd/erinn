Description

core/db/otel_schema.go defines idx_otel_feature_ts on otel_signals(feature_id, ts_micros). feature_id is written on those rows and selected for display, but a tree-wide grep finds zero queries filtering on it — every reference is either a display pass-through or a correlated subquery keyed the other way, on the small features table. The index was evidently built for per-feature OTel rollups that were never implemented. otel_signals carries nine indexes totalling about 14MB. Either drop the index, or build the per-feature failure-rate and cost rollups it was intended for, which the schema already supports.
