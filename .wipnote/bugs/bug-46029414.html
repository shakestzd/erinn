Description

SessionStart schedules retention without serve, but SweepNDJSON requires each .index-offset to cover the full events.ndjson size. Post-cutover the indexer is constructed only by serve-child or explicit reindex, so projects that never run serve rotate logs but never reclaim raw telemetry. Documentation claiming reclamation without serve is therefore misleading. Retention coverage must come from canonical sealing/rollups rather than a dashboard index checkpoint.
