Codex subagent assistant text is mislabeled as Claude Code

Todo High Priority

Caused By:

  • Wire Codex per-subagent identity end to end

Part Of:

  • trk-c4615ad2

Description

Now that the Codex agent id is no longer discarded, two switch statements that assumed every Codex event carried the generic constant are wrong. The transcript assistant harness resolver switches on the event agent id with a case for the literal codex string and a default returning the Claude harness name. A genuine Codex subagent now carries its real agent id, falls to the default branch, and has its assistant-text records labeled as Claude Code. This is a shipped regression, not an improvement, and it silently corrupts harness attribution on transcript records. The fix is to switch on the event harness field rather than the agent id, which is now the correct discriminator since the agent id can legitimately be any subagent name. A second site, the subagent detection predicate, has the same assumption but the opposite consequence — it now correctly classifies Codex subagents as subagents, which is a correctness improvement, but it means subagent-scoped guards that never fired for Codex before will begin firing. Decide that one deliberately rather than letting it ride as a side effect.
