Description

A runtime check of the installed Codex CLI 0.147.0 lists 104 feature flags with stage and effective state, including one named use agent identity at stage under development with effective state false. The cross-harness audit concluded Codex exposes per-subagent identity because the generated JSON Schema declares the fields on five hook events — but those are optional properties, which is exactly what fields gated behind a disabled flag look like. Neither the prose documentation nor the schema surfaced the flag; a single command did. Before wiring the Codex arm of the identity seam, capture a real hook payload and confirm whether the fields are populated with the flag off, populated only with it on, or never populated in this version. Each outcome implies a different plan, and the worst case is shipping an adapter that claims a capability the binary does not have. Related flags for context: multi agent is stable and enabled, multi agent v2 is stable but disabled, hooks is stable and enabled.
