Subagent write guard fails closed once the yolo grace window expires

Todo High Priority

Part Of:

  • trk-2c55adea

Description

checkSubagentWorkItemGuard derives hasAgentClaim from claimedItem, which is sourced entirely from the claims table. That table has zero production writers of a new row, verified by tracing the one code path whose own comment claims to create one and finding it calls only recordClaimEpisodeOpen. So claimedItem is always empty and the guard always fails. Once checkYoloSubagentGrace's 30 second window closes, every subagent Write, Edit, MultiEdit and apply_patch in yolo mode is blocked with no claimed work item, regardless of whether the orchestrator legitimately started one. This fails closed rather than open, so it is an availability defect rather than a security one, but it makes yolo subagents unable to write after 30 seconds.
