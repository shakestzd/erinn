Description

Follow-up defect in the session guard shipped in commit 2d54416ed. core/hooks/session_html.go:154 guard writes when on-disk article id == s.SessionID, but a SessionStart replay/resume with the same session id and a fresh 0-event shell still overwrites a populated/completed session, resetting data-event-count to 0 and dropping the activity log. Make CreateSessionHTML idempotent: if the target file exists with recorded events or completed status, preserve it (no rewrite), only safe-patch metadata. Add regression test: existing same-id file with events/completed is NOT reset.
