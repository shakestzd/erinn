Completion gate reads a commit index with no automatic refresh

Todo Medium Priority

Part Of:

  • trk-2c55adea

Description

Work item completion refused with zero linked source commits for a commit that existed and correctly carried the work item id in its message. The cause was not attribution: the commit index is a derived table populated only by an explicit ingest or reindex step, and no post-commit hook refreshes it, so it was over an hour stale. Running the ingest command backfilled the commit correctly and completion then succeeded with no override needed. This is distinct from the claim misattribution being fixed elsewhere in this session, and it has been misdiagnosed as such at least once — including by me. The user-visible effect is a gate that reports an absence when the fact exists, which pushes people toward override flags for a condition that a refresh would clear. Either refresh the index before the gate reads it, install a post-commit hook, or have the gate fall back to inspecting git directly when it finds nothing.
