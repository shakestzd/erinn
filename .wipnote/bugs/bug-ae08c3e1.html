Description

The success field is now derived from an explicit success boolean attribute rather than OTLP StatusCode, which Claude Code almost never sets. The Codex, Gemini and Antigravity adapters share the identical StatusCode-only pattern and are very likely affected the same way, but the fix was deliberately scoped to Claude because the live index is essentially all claude_code traffic — 39574 of 39859 rows — leaving no real captures to verify what attribute shape the other harnesses actually send. Guessing was correctly declined. Revisit with real captures when those harnesses see traffic, and verify each adapter against its own vendor documentation rather than assuming the Claude shape generalises.
