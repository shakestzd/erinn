Subagent git commits are not linked to work items in real time, forcing manual link-commit or ingest

Todo Medium Priority

Part Of:

  • trk-08dcbb33

Description

Observed repeatedly across a multi-agent session on 2026-08-07. Subagent git commit calls do not land in the git_commits table as they happen, so wipnote bug/feature complete refuses with 'zero linked source commits' even when the work is genuinely committed. Agents worked around it two ways: running wipnote ingest commits to backfill, or calling wipnote {bug,feature} link-commit manually. At least five separate agents hit this in one session, and the orchestrator had to link commits by hand for most completions. Either the commit ingestion should fire on subagent commits, or the completion gate should attempt a backfill ingest before refusing. Cost today is silent friction that reads as a provenance failure rather than a plumbing gap.
