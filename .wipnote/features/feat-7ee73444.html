Description

Compute per-work-item outcome facts from otel_signals (attempts, gate failures, error rate, wall-clock, cost_usd, tool failure breakdown) AND PERSIST THEM INTO THE WORK ITEM HTML as data attributes, not only as a live query. Persisting to the canonical store is the point: it makes the aggregate durable past any raw-row retention window, git-diffable, and visible to every CLI path agents already read. computeOtelStats in api_tree.go proves the query shape (SUM over success=0 grouped by trace_id) — it is just scoped to one dashboard render and never rolled up per work item. The dead index idx_otel_feature_ts was evidently added for exactly this aggregation and no query ever used it, so this feature either justifies the index or retires it. Acceptance Criteria Rollup facts appear in the work item HTML and survive a full cache wipe plus rebuild. Backfill covers the existing corpus. Must land and backfill BEFORE any retention policy prunes raw rows, or the history it would distil from is gone.
