claim_episodes table missing from every existing index, so the projection fails on every run

Todo High Priority

Part Of:

  • trk-2c55adea

Description

The claim episodes table is declared in the create-all-tables path but was added without a versioned migration step. That path runs only at schema version zero, so no database that already existed ever receives the table. Confirmed on the live index: the table does not exist while the schema version reads current. Consequence: the claim-episode projection fails on every reindex with a missing-table error, so the canonical claim ledger has never once been projected into the index it is supposed to feed. This is the same defect class as the attribution-column bug fixed earlier — a column or table added inside a first-run-only path silently never applies to existing databases — and it is the second instance, which makes it a pattern rather than an accident. Fix with a real versioned migration step, and add a guard test asserting that every table in the create-all path either appears in a migration step or is provably new-database-only. Note the gate ledger's own step deliberately tolerates a missing table for exactly this reason, so the workaround is already spreading.
