resetOtelCheckpoints deletes index offsets shared with a possibly-running daemon

Todo Medium Priority

Part Of:

  • trk-2c55adea

Description

The per-session index offset file is the same checkpoint the live dashboard daemon reads and writes, and it is also consumed by session-end catch-up waiting, session pruning, and the retention sweep. The reindex path deletes that file for every session unconditionally, with no lock and no check for a concurrently running serve daemon. This is an unguarded pre-existing race, mitigated only incidentally by insert-or-ignore idempotency on the signal id — so the visible symptom is duplicated work rather than corruption, which is why it has gone unnoticed. It is not introduced by the bounded-snapshot redesign, but that redesign is the natural moment to fix it, since both concern who owns the checkpoint. Establish whether reindex should refuse to run while a daemon holds the checkpoint, coordinate through the existing lease mechanism, or use a separate checkpoint namespace of its own.
