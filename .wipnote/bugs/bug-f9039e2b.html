bug create auto-links caused_by the active feature, fabricating false lineage

Done Medium Priority

Caused By:

  • feat-801f2273

Part Of:

  • trk-0677c709

Description

When a bug is created without an explicit --caused-by, cmd/wipnote/workitem_create.go:179 falls back to detectActiveFeature and links the new bug caused_by whatever feature is currently in-progress. This fabricates a causal edge: a bug about unrelated functionality gets attributed as caused_by the active work. Observed live this session: bug-b9d0e3e0 (YOLO worktree isolation) was auto-linked caused_by feat-801f2273 (plan-review consolidation) solely because that feature was active; the edge was wrong and removed manually. Because lineage/causal provenance is wipnote's headline capability, this silently corrupts it across any session where bugs are filed while a feature is in-progress. Required behavior: on new-issue creation, do NOT default caused_by to the active feature. Instead the orchestrator/CLI should find the CONTENT-relevant track and feature(s) via relevance search over the issue text and link the bug to those; set caused_by only when explicitly provided or content-justified. If nothing relevant is found, leave it linked to its track only rather than asserting a false causal edge. Fix location: cmd/wipnote/workitem_create.go:179 (the detectActiveFeature fallback for caused_by).
