Description

A single recommend invocation calls the graph loader directly and then calls three analytics functions, each of which independently loads every node again. There is no caching anywhere in the graph or work item packages — no sync.Once, no package state — so one command pays roughly four times the full corpus parse, about 430 milliseconds against a measured 108 millisecond single load. This is a present-day cost independent of any architectural change. It also matters as a prerequisite: any proposal that moves more readers onto in-memory loading multiplies this, so a per-invocation cache should land before rather than after. The cheapest fix is threading the already-loaded node set through to the analytics calls rather than having each re-read from disk.
