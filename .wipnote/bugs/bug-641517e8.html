CSS scoper treats an apostrophe inside a comment as a string literal, silently unscoping the rest of the stylesheet

Todo Medium Priority

Part Of:

  • trk-a951e3c0

Description

cmd/wipnote/plan_css_scope.go treats an unpaired apostrophe - including one inside a CSS comment - as the start of a string literal, and silently stops scoping every rule after that point. Half the embedded plan stylesheet ends up unscoped with no error raised. Found during feat-f8644765; a warning comment was added to the stylesheet as a stopgap but the scoper itself is untouched. Needs a real fix plus a test with an apostrophe in a comment.
