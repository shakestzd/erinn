Description

Telemetry is ingested from per-session NDJSON into a table that costs 377 seconds of every full rebuild, holds 61 thousand rows and the clear majority of a 145MB index, and is read by nothing behavioural — only dashboard endpoints. The NDJSON is already the source of truth and already in canonical shape: kind, signal id, session, canonical name, native name, timestamp and an attribute bag, matching the table's own columns. The driver bumped tonight carries a virtual-table subpackage, verified working by prototype at 65 milliseconds for a grouped aggregate across a thousand shards, in pure Go with no ingestion step. THE DESIGN DECISION THAT MAKES THIS BETTER THAN A PORT: the work-item attribution column appears nowhere in the stream — zero occurrences — because it is resolved at ingest by consulting whichever work item was claimed at that instant, from the single mutable slot this session proved was wrong. So attribution is currently frozen into each row from a broken lookup. Instead, derive it at query time by joining a signal's timestamp and agent against the canonical claim ledger, which records work item, agent, start and end as intervals. Historical signals then re-attribute correctly as the ledger improves, rather than carrying a permanent stamp from a defective read. PHASES: first a virtual table over the shard directory with constraint pushdown so a session-scoped query opens one file rather than scanning all — the prototype confirmed the index-info plumbing delivers real constraints. Then move the dashboard readers. Then attribution as a join. Then retire the ingest path, which is the 377 seconds. Retention becomes deleting old shard files rather than pruning rows, which is simpler than the prune that cost eighteen minutes per rebuild before it was fixed. TWO KNOWN GOTCHAS from the prototype, both non-obvious: module registration affects only connections opened after the call, so any query or ping beforehand leaves it unregistered on that pooled connection; and arguments in the create-virtual-table clause arrive as raw unparsed text with quote characters included. SCALE CAUTION: one live shard is 160MB and 124 thousand lines, far beyond the prototype's fixture, so measure against the real corpus before committing to a full-scan design and lean on pushdown.
