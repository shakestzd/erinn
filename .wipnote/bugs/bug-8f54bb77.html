wipnote continue cannot resolve which worktree to resume into

Todo High Priority

Part Of:

  • trk-2c55adea

Description

ListHarnessGroupedResumableSessions selects six columns per resumable session that now have no canonical source at all: exec_worktree_path, branch, handoff_notes, recommended_next, blockers, and last_activity. All were written by the SessionEnd hook into the persistent sessions table and exist nowhere else. Verified against both candidate sources: sessionledger.Record carries only SessionID, Harness, ProjectDir, StartedAt, EndedAt, EndSource, ArchivePath and Events; session HTML carries data-active-feature-id but no worktree, branch or handoff attributes, confirmed by grepping the real corpus. Consequence: wipnote continue resolves WorktreePath empty and cannot reconstruct which worktree to resume into. Ten tests report this, four of them asserting WorktreePath directly. No fixture work can fix it because the data does not exist anywhere. Related to bug-d76f588a, where SessionEnd was found to discard five of its six writes including the handoff fields. Requires a decision: extend the session ledger record with resume fields, add the attributes to session HTML plus a hydration pass for them, or accept that continue degrades to fresh-start and change the tests to assert that.
