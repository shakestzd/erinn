purge-spikes full-reindex path erases plan, session and arch edges on every run

Todo Medium Priority

Part Of:

  • trk-2c55adea

Description

The full-reindex helper inside the purge-spikes command calls the stale-entry purge with a valid-id set holding only tracks, features, bugs and spikes, and no edge pass runs after it. Every plan-targeted, session-targeted and arch edge is therefore deleted on each invocation. It self-heals on the next ordinary reindex, which is why nobody noticed, but between the purge and that next reindex every lineage and graph query silently returns an amputated graph. Found during the tombstone work, which pinned its own survival at the function boundary precisely because no end-state census can see this window. Fix by feeding the same classifier the main path now uses, or by running the edge derivation passes after the purge, and add a function-boundary test the same way the tombstone survival was pinned.
