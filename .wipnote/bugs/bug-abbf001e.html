Description

During 'wipnote claude --dev' continue flow (selecting an existing work item to continue), the launcher creates/rehydrates the work-item-keyed worktree and runs a reindex inside it. The reindex is killed by a signal: launcher prints 'Warning: reindex in worktree failed: signal: killed'. Likely OOM (reindex builds the full SQLite read index and is memory-heavy in the devcontainer) or a process-group/timeout kill during launcher handoff. Impact: the worktree read index (dashboard/queries) is stale or empty after continue, degrading the rehydrated continuation. Repro: wipnote claude --dev -> choose Continue for an item whose previous worktree is missing -> observe the reindex warning. Investigate where reindexWorktree is invoked in the continue/launch path, whether it runs under a memory cap or short-lived process group killed on handoff, and whether to retry or surface more loudly. NOTE: --files path is a best-guess; confirm the actual reindexWorktree call site before fixing.
