Description

The adapter conformance table states that the Codex prompt id is synthesized from a conversation id plus a sequence number. The code does no such thing — it reads a single attribute verbatim and otherwise leaves the value empty. The comment is stale. Worse, no test anywhere in the package asserts the prompt id for Codex at all, despite the table implying coverage, and unlike neighbouring tests that carry an explicit empirical or captured provenance note, there is no evidence the attribute has ever been observed in real Codex traffic. If it does not appear, the prompt id is silently empty for every Codex signal and nothing would reveal it. Fix the comment, add coverage, and — since a separate audit found the vendor publishes no attribute-level schema for its telemetry at all — verify against real captured output rather than documentation, because in this case documentation does not exist.
