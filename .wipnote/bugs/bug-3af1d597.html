Description

wipnote relevant <topic> returns recap-*.html files as top hits with score 98 because recap artifacts embed full git diffs as HTML, so their text matches almost any query term. Real features, bugs, spikes and tracks are pushed below the fold. Observed searching for performance/benchmark/telemetry topics: every top result was a single recap file citing diff lines. Effect: the documented first step for finding existing lineage before creating work items does not work on a repo with recap artifacts. Suggest excluding recaps from relevant by default, or weighting by item type, or adding a --type filter.
