Description

Two confirmed fail-open edges in Codex 0.147.0 hook responses, both verified live. First: a single UNKNOWN field inside hookSpecificOutput silently defeats a deny — the block is dropped with no error. wipnote's struct is schema-clean today (only the four fields Codex declares) but any future field addition silently disables gating. Second: exit code 2 with EMPTY stderr is silently treated as ALLOW, not deny; non-empty stderr blocks and supplies the reason. All three BlockExit2Error call sites currently format non-empty messages, so this is latent rather than live. Both need pinned regression tests, since either would disable enforcement with zero signal.
