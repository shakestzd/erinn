Description

core/hooks/harness.go retains ToolResult-adjacent fields task_id and task_subject, left in place under bug-9f49a375 as unconfirmed because no captured payload populated them. Now resolved: binary analysis shows task_id appears only inside Codex Cloud's RawRecord task-tracking schema, alongside encrypted_task_id, max_concurrent_threads_per_session and job_max_runtime_seconds — a different subsystem entirely (codex cloud). task_subject appears zero times anywhere in the binary. Neither is in any of the 11 hook payload JSON schemas. Remove them from the hook struct. Notably this misattribution of Codex Cloud task vocabulary to the hook system is the likely origin of the phantom TaskStarted/TaskComplete event registrations.
