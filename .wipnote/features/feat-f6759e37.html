Description

Hooks are fresh processes and cannot afford to parse canonical state, which is the only reason they read the derived index. The fix is a read path on the resident process that already exists — the headless mode already runs the socket listener, write queue and background maintenance without the dashboard, so this is adding a capability rather than building a service. AVAILABILITY POLICY, decided: the launcher owns it. A session started by a wipnote launcher guarantees the daemon — the launcher ensures it is running, attaching if one already exists, and writes its socket path into the session environment alongside the variables it already sets. Hooks then do not negotiate availability; they read the path and use it. If the daemon becomes unreachable mid-session, hooks retry a bounded number of times and then REPORT LOUDLY and pause execution gracefully. They do not silently fall back to a different data path — a quiet fallback is how two code paths diverge without anyone noticing, which is the defect class this whole track exists to remove. A session NOT started by a launcher has no such guarantee and must work without the daemon, reading as it does today. That is two behaviours, but the mode is explicit and announced rather than inferred: the launcher already writes a launch marker, so a hook can know which contract it is under and say so. Ownership follows from the same rule — the launcher starts or attaches, and never stops the daemon on session exit, so a shared daemon outlives any one session. Scope includes the socket read protocol, which today has five write ops and no reads, and a parsed-canonical cache with an invalidation story, since serving stale work-item status to a guard is the failure this must not introduce.
